# Originating session request boundary

Beta contextual requests bind `X-Compass-Session-Binding` to the opaque binding from the originating rendered `/api/account/session` response. The server validates the cookie independently and rejects absent or mismatched bindings with `409 session_changed` before route handlers, including contextual catalogue/recommendation reads, profile/settings, manual performances, favourites, export, deletion and cookie transitions. Ownership remains exclusively cookie derived; bindings are neither user IDs nor authentication credentials. Same-account replacement sessions have distinct bindings.

Explicit exceptions are OPTIONS, health, authoritative session bootstrap, and OTP sending. OTP sending only creates verification records and sends mail with the pinned Better Auth sign-in OTP route; it does not create/refresh an authentication cookie. Login and logout require a binding even when signed out (`signed-out`); an old signed-out login intention cannot replace a newly authenticated session. Anonymous catalogue requests remain available when no cookie/binding exists. Private signed-out requests remain 401. All API responses remain private/no-store.

All rendered contextual operations capture an immutable origin, acquire the same `5k-compass-auth` Web Lock as cookie writes, then authoritatively revalidate the session. The lock lasts through the complete dispatched response, including its body. Cancellation while queued prevents dispatch; cancellation after dispatch discards the result but cannot release the lock before response completion. Browsers without Web Locks fail closed. The existing H1 history boundary remains intact and calls the bound raw history transport under its existing lock, avoiding recursive lock acquisition. Mutations retain the originating dispatch closure through rerenders/retries. Export uses the same boundary; deletion/login/logout already own their cookie-write boundary and now check bindings too. Notifications are only an optimization.

Public history/analytics query caches contain only shared aggregate facts; personal query caches are cleared across auth epochs. Private UserPerformance evidence stays private, and M1 edited-date replay is unchanged.

Cached clients predating this contract deliberately fail closed: unbound login and authenticated contextual requests receive 409. They must activate/reload the current client before signing in or continuing personal operations. There is no old-client binding bypass. The real cached-shell upgrade test establishes a synthetic bound session explicitly before loading old cached assets, verifies rejection and unchanged private records against the current API, then activates the current worker and performs a bound import.
