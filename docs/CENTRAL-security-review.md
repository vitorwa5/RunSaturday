## Initial audit of selective reuse candidate `50c9134`

Recommendations were sent to the developer, independent QA and coordinator before implementation completed.

- **High:** its immutable header transport does not acquire the shared authentication Web Lock or revalidate after acquisition. General contextual requests must retain the originating identity and share the cookie transition lock through response completion. Preserve the reviewed H1 `captureHistorySession`/`withHistorySession` implementation; avoid recursively obtaining its non-reentrant lock from history dispatch.
- **High:** its `usePerformanceMutation` invokes a lexical `fn` rather than carrying the originating dispatch in mutation variables. A retry after a render can adopt the replacement transport. Preserve H1's captured dispatch and session in mutation variables for all mutations. The candidate also predates and would remove H1 history revalidation if overlaid wholesale.
- **High:** cookie transitions must compare session binding, including same-account replacement, and send the binding checked under the lock. A signed-out login must send the explicit `signed-out` intention and refuse a replacement signed-in cookie.
- **Medium:** requiring the header deliberately breaks old authenticated clients across the contextual API. Missing headers must fail closed; any reload/update guidance must not silently acquire a replacement binding for an old operation. Re-run real cached-client compatibility beyond B4's body-only contract.
- **Medium:** bootstrap/health/OTP exemptions require an explicit inventory. All API replies must retain `Cache-Control: private, no-store`. Exceptions must not create an alternate cookie transition path.

## Static boundary inventory

Contextual catalogue list/search/nearby/detail includes saved origin and user context. Saturday/planner/best-pick, placement, event placement, PB finder, hidden gems and comparison use personal context. Profile/settings, manual performance CRUD and summaries, Current Form, challenges/opportunities/visits, history preview/commit/withdrawal, account export/deletion and login/logout require originating-session protection. The current source has no separate favourite mutation route; favourite records are private in contextual data and export and are removed by account deletion.

`events/:id/history` builds public occurrence history, and `events/:id/analytics` reads aggregate catalogue analytics without personal context. Their existing nonpersonal query keys are appropriate only while those responses remain public facts. A transport may conservatively bind them while signed in.

The authoritative session bootstrap necessarily reads authentication identity before a binding exists. Health and OTP-send do not select personal data. The pinned installed Better Auth email-OTP `sendVerificationOTP` implementation (`dist/plugins/email-otp/routes.mjs`, lines 75–121) creates/rotates a verification and sends the email; it does not invoke `setSessionCookie`. The wrapper forces `type: sign-in`; session refresh and cookie caching are disabled. This supports a narrow OTP-send exception, subject to dependency changes.

Cookie ownership must remain authoritative: the binding is a precondition, never an owner selector. Existing H1 origin capture, shared lock acquisition, post-acquisition authoritative revalidation and response lifetime must remain. M1 calendar-date replay and private performance provenance must remain untouched.
